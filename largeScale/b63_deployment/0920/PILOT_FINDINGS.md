## 特征可识别性

`extractTopology.py` 从既有 214-Pod 实验的 `k8s.source.yaml`、Dockerfile 的 COPY 映射、BIRD 配置和网络报告提取特征，不采用旧报告的人为 CPU/Memory 数值。提取到：450 个网络接入、230 个 iBGP 会话端点、36 个 eBGP 会话端点、236 个配置可形成的 OSPF 邻接端点。全部 OSPF 关系通过双向一致性检查。

样本只有 7 种不同特征组合，并且全部满足 **nnet = 1 + nOSPF**。因此 `[1,nnet,niBGP,neBGP,nOSPF]` 的秩为 4，不能辨识 5 个独立系数。岭回归虽然能产生一个数值解，也不能消除这种可识别性问题。需要增加具有额外非 OSPF 接口、不同活跃 OSPF 关系数的标定拓扑，并按拓扑家族保留测试集；否则只可以报告该低维拓扑族中的预测能力。

该解析器支持显式编译生成的 BGP 会话、OSPF area/接口；不声称是通用 BIRD 语法解析器。配置层关系不等于运行时 Established/Full，就绪还须独立验证。

## c2m2 第一个完整区块

首尾基线最大相对漂移为 0.57%，观测最大 steal 为 0.063%。在当前固定 SHA256 canary 下：

| 后台 CPU 需求/2核 | 驻留内存比例 | Q（吞吐比与逆 p95 比的较小值） |
| --- | --- | --- |
| 0.0 | 0.0 / 0.35 | 0.995 / 0.993 |
| 0.4 | 0.0 / 0.35 | 0.961 / 0.989 |
| 0.7 | 0.0 / 0.35 | 0.370 / 0.370 |
| 0.9 | 0.0 / 0.35 | 0.370 / 0.370 |

此处只是一轮区块，无置信区间。Q 的主要下降来自 p95 从约 4.7 ms 上升到约 12.7 ms，吞吐也下降。CPU 目标 0.4 到 0.7 之间存在 η=0.8 的边界，下一轮应加密该区间。只分配/驻留 35% 内存尚未带来明显附加干扰；这不能推导出内存带宽压力也无影响。

CPU 目标 0.7/0.9 时实际后台获得的 CPU 小于目标，原因是 canary 与后台共同争用固定 CPU 能力。输入必须继续使用独立需求/配置预算，不能改用已被争用压低的实际 CPU 作为部署前预测特征；实际 CPU 仅用于诊断执行与争用。此轮 canary 是一个闭环、单线程、固定任务量服务，其画像不能未经验证泛化到任意应用。

内存 0.7 的 4 个点全部被预设余量检查拒绝。VM 的系统开销加上 20% 可用内存余量不允许这个分配量。它们记录为 `rejected_memory_headroom`，不是测得 Q=0，也不是可训练点。后续将使用可运行的 0.6 点补足二维范围，原始失败记录保留。
