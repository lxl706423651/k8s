## 1. 研究问题与可执行模型

依据所给PDF，将每个虚拟网络建模为超边。Pod放置在异构VM上，最小化按超边全部成员对归一化的跨VM通信切分代价；资源容量、Pod slots、CNI/VLAN兼容性和`Q >= eta`均为硬约束，默认`eta=0.8`。没有引入通信收益与争用损失的任意加权和。

路由基础需求使用`[1,nnet,niBGP,neBGP,nOSPF]`非负回归，加用户显式额外CPU/内存预算。未知程序不按任务类型分类。VM服务能力由固定canary测量：持续执行8×1MiB SHA256任务，`Q=min(吞吐/参考吞吐, 参考p95/当前p95)`。因此本文讨论的是该VM级服务能力代理，不是任意应用的完成时间保证。

`solvePlacement.py`实现多起点贪心构造及move/swap/group改进。每次接受变更均重新执行全量目标审计；无法构造解不等于已证明不可行。`exportDeployment.py`重新审计映射与源清单，输出nodeName、镜像清单及约束证据；不认识的调度约束直接拒绝。

有效Pod预算、背景占用及画像轴必须一致。训练注入比例不能直接代替K8s allocatable比例。具体转换、固定canary开销及中心预测/接纳下界的区别见[MODEL_SCOPE.md](MODEL_SCOPE.md)。

## 2. 算法证据：正确性与求解质量分开

- 729个映射使用独立成员对公式验证通信目标；17,671个增量候选与全量计算对照，最大数值差约`7.1e-15`。
- 20个小实例与穷举最优解比较，15个达到最优，最大绝对gap约1.4709。启发式不声称全局最优。
- 24/48-Pod、3个种子、7种方法共42次合成实验。完整方法通信代价中位数2.80/9.69；取消Q约束后为0/4.20，但出现模型违约节点。
- group和多起点并非每个实例都有收益，保留无收益案例。214-Pod/18-VM合成实例约119.5秒完成一次求解并通过完整约束审计。

这些是**算法和合成画像**证据，不作为真实VM性能结果。详见[ALGORITHM_FINDINGS.md](ALGORITHM_FINDINGS.md)。

## 4. 原二维Q画像：明确未通过全部精度要求

三种规格分别训练、独立校准。c2m2和c4m4原校准遇到低压力下显著尾延迟下降，经验余量使空载预测下界低于0.8，因此守门逻辑停止，原保留测试未启动。

c4m2进入原独立测试：6个CPU点×3个内存点×3种实现×5块，共270点。固定模型得到：

| 指标 | 结果 | 预设要求 |
|---|---:|---:|
| MAE | .07301 | ≤ .08 |
| 块bootstrap的MAE 95%区间 | [.06675,.07916] | 描述性区间 |
| P95绝对误差 | .52677 | ≤ .15，未通过 |
| 接近η的32点MAE | .49541 | 必须单独报告 |
| 预测安全点的观测违约 | 0 / 180点 | 不是180个独立部署 |

不能用平均误差达标或0/180替代P95失败。相同设定CPU/内存输入下观察到跨越η的结果，但旧控制器存在实际CPU跟踪偏差，不能直接将其解释为等实际预算下的二维模型反例；下文保留这一混杂因素。

后续改进保持原结果：对低压力域拟合经验下包络，用新独立校准和测试检验；对c4m2追加拐点训练，将条件中位数中心预测与接纳下界分开。尚未完成的新测试不列入通过结论。图见`results/transfer-limits-figures/transfer_limits.pdf`。

## 5. 实际部署真实性与实验独立性

实际集群为独立新建K3s控制节点加2CPU/2GiB、4CPU/2GiB、4CPU/4GiB三个worker，独立管理网与VLAN trunk。实验VM绑定宿主CPU，但未声称获得独占物理核。既有E1B集群仅用于只读镜像导出，未向其增加试验负载。

214个镜像的摘要、配置与层校验，1712个编译COPY文件字节比对及三worker预拉取均保留。两个资源诊断分布的214个Pod均Ready、实际映射一致；全部214工作负载的预期协议/BGP/OSPF通过，固定3个AS代表通过独立BIRD与FIB检查。命令返回0本身不作为协议成功证明。

资源采集前测空背景，采集180秒并扣除采样器CPU，父子cgroup分层报告而不相加。第二轮清理后的首空窗口有回收瞬态，**在验证负载产生前**决定补测稳定背景，保留原窗口和干预记录。后空canary参考在删除后固定冷却180秒再测，避免把回收活动作为资源充沛参考。

真正的Kubernetes默认调度器对照已完成部署、BIRD、协议和canary采集；其中一个节点的主canary窗口被内存保护拒绝，Q未知。它保留相同214镜像、容器内容和零额外任务预算，只限定相同worker候选集，实际落点由调度器产生。完整性限制与补充诊断见第8节。

## 6. 当前能支持与不能支持的结论

已有证据支持：目标与约束实现可审计；启发式质量/局限可量化；编译特征在受控路由状态中能预测容器需求；增加独立测量的平台开销项显著改善一次新分布的节点需求预测；真实214-Pod的镜像、映射、协议和FIB验证链可运行。

当前不能支持：所有未知任务仅凭平均CPU/内存预算都满足η；原Q模型达到预设精度；一个或几个部署块达到“违约概率单侧95%上界≤0.10”；只报告容器需求就足以规划K3s容量；逻辑通信切分减少等于实测带宽或时延改善。

第二轮匹配空参考后的实测最低Q为c2m2=.97199、c4m2=.96240、c4m4=.95397，参考漂移均<.14%。该部署Q良好，仍不是模型预先接纳的方案。

对现有裸VM画像做显式背景/有效容量坐标转换后，η=.8时节点Pod数量的乐观上界合计仅110，小于214；η=.7/.75时也仅195。此为给定经验模型实例的必要条件证明，不是硬件容量不够或贪心搜索失败。该判定器在24个小实例、5832个穷举映射上检查，没有产生错误不可行证书。原模型把实际可工作的场景拒绝，进一步说明需要在最终K3s worker环境标定，而不能直接共享裸VM规格画像。

目标worker的低压力域重新标定已于23:13启动，单独使用训练/校准/测试；保留所有旧失败。完整方法的实际模型接纳、实际η扫描及剩余独立测试仍需完成。若某规格或场景不能接纳，应报告拒绝/不可行及其证据，不能手工放宽η或换画像来制造成功。

## 9. CPU预算跟踪审计与新协议（23:22更新）

旧控制器每50ms重新给CPU预算，没有扣除工作块超调和循环开销。c2m2低压力包络测试的90个预测安全点中5点Q<.8，均为stream、设定CPU比例.017，实际约.0279–.0284，超出设定64–67%。这些是真实观测违约，原统计保留，但不能证明等实际预算下的实现迁移失败。

事后诊断容差为`max(设定比例×2%, .0001)`：c2m2、c4m4各150点中integer/resident/stream分别40/50、50/50、50/50超预算；原c4m2的270点中stream15/90超预算，另有多点高负载未达到目标。该容差对旧数据是事后审计，不删除旧点、不重新计算“通过”指标。审计见`results/*budget-audit.json`。前述原画像不可行证书也仅对这些经验画像成立，不能排除控制器偏差的影响。

目标K3s worker使用独立`measureNodePressure.py`，以累计进程CPU债务补偿超调，并在采样前冻结相同跟踪容差；超差使新模型数据校验失败。固定canary函数保持一致。三worker最终训练均105点：CPU={0,.005,.01,.02,.04,.08,.12}、内存={0,.25,.5}、resident、5块；新校准120点含resident/stream；测试150点含三种实现，integer不进入本轮训练/校准，但在整个项目中并非从未见过。内存保护改为15%且至少64MiB，这一独立协议不替换旧默认对照的拒绝记录。

训练开始前已修正控制器；校准和测试开始前又将stream工作块从1MiB减到64KiB，resident训练路径不变。原因是空闲VM预检的.003流式目标仍有.000118偏差，超过已冻结容差；未放宽容差。64KiB版六项VM预检全部通过，.003流式实际为.0030134。源码及干预记录在`results/node-calibration-sources/`，每批实际归档源码为准。这是仪器跟踪检查，不代替新Q画像的独立测试。

默认c4m2补充3点Q为.96210/.93756/.93225，参考漂移.004268；主15点仍全部无有效Q，不用补充点替代，也不将窗口计为独立部署。


该审计并不解释掉所有旧异常：c2m2的20点低负载顺序诊断中，CPU=.1的10次实际比例为.10164–.10251，而Q跨.399–1.000；其中全部7次Q<.8均在事后2%跟踪容差内。CPU=.4的10次Q均>.997且跟踪合格。它仍说明简单平均预算/单调响应假设值得检验，但这些是旧控制协议的顺序诊断，不是修正后新模型的独立测试，不能事后挑选7点作为新的测试集。见`results/c2m2-lowload-budget-audit.json`。

默认调度主窗口的另外两节点有效：c2m2最低Q=.98614、c4m4=.92950，均无观测Q<.8；由于c4m2主窗口无效，整个默认部署的三节点主Q结果仍不完整。

### 二维中心预测在c2m2测试集上的有限样本限制

在不改变测试结果的事后可辨识性分析中，按相同指令CPU/内存预算分组，对每组任意单值预测的最小L1由该组中位数达到。对全部150点求和得到最小可能MAE=.0884009，已超过预设.08；实际模型MAE=.0949782。此下限甚至允许完全知道测试答案、非单调、任意复杂的二维函数，因而单纯更换拟合器无法使这批观测达到MAE门槛。

进一步，误差≤.15的观测必位于以预测为中心、宽度.30的区间。逐组滑动寻找最多可覆盖观测数，CPU=.09、内存=.1/.425两组各至少7点不可覆盖，总计至少14/150点误差>.15；这也足以违反当前线性插值经验P95≤.15的门槛。此算法用200组随机样本的独立断点穷举及边界用例检查。原始数据入口重新核对全部CPU跟踪、实际CPU范围、参考漂移和固定canary，结果见`results/node-c2m2-test-ambiguity-bounds.json`。

上述结论只适用于同一指令预算作为输入的有限观测集。实际CPU有公差内波动，不能据此证明对精确实际CPU或所有未来工作负载的总体不可能性；用实际CPU或实现标签事后区分这些样本会改变当前预算预测问题。c4m4同样分析的最小MAE=.01946、误差>.15必然点数为0，不能用c2m2结论概括所有规格。
