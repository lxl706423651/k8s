# 实验设计与完成审计

冻结日期：2026-09-20。下列门槛在新的训练/测试结果产生前指定；若改变实验设计，要保留原因与旧版本，不能根据测试表现调阈值。

## 研究命题与约束

1. 拓扑可得特征 nnet、niBGP、neBGP、nOSPF 能在明确路由规模/协议状态范围内预测路由 CPU 和工作集。仅这四项无法识别的路由表大小差异须作为边界报告。
2. CPU/Memory 压力能预测固定 canary 的 VM 服务质量，但并不自动保证任意额外任务的性能。η 固定为 0.8。
3. 满足性能约束的通信优化，比资源均衡或仅局部性优化取得更好的通信成本与实测违约率折中。

## 实测与独立性

- VM 标定：至少两种 CPU 规格和两种内存容量组合；每种独立扫描 CPU、驻留内存，再补充联合压力点和 Q≈0.8 附近的点。记录施加预算与实际 CPU、RSS、PSI、steal、canary 完成量及延迟。内存驻留和内存带宽不同，必须分别检查，不能把二者混为内存用量。
- 基线：每个随机化实验区块前后采集无压力基线，保留漂移；将单次实验按当区块基线归一化。Q=min(throughput/ref, latency_ref/latency)，延迟具体统计量在首轮正式实验前固定。零完成、超时、OOM 和连接错误保留为失败，不用幸存样本填补。
- 重复：正式点至少 5 次独立重复；同一运行窗口的高频采样不算独立重复。报告区块 bootstrap 的 95% 区间。
- 划分：训练用于拟合，独立校准用于一侧残差余量，最终测试按压力组合、随机种子和拓扑家族分组保留。不得使用最终部署效果重新拟合后再把同批数据称为测试集。
- 路由资源：覆盖四个特征的不同组合，检查设计矩阵秩/共线性；对每个样本保存 BIRD 配置、协议就绪状态、路由数量、CPU 和内存原始观测。固定测量阶段（稳态/收敛期分别分析），非负线性或岭回归由训练集选择。
- 额外任务预算一致性：相同 CPU/Memory 上限下，至少三种实现方式，保留一种作为完全未见实现。若两维输入不能区分干扰，明确报告反例和边界，不事后添加“任务类型”标签使结果变好。
- 迁移：先各 VM 类型拟合，只有跨类型保留测试误差支持时才合并曲线。

## 优化与部署验证

- 小实例对照穷举最优值，报告 optimality gap，不声称启发式全局最优。
- 中/大规模报告耗时、候选数量、失败构造次数、随机起点差异。
- 对比：相同资源和部署约束下的 resource-first、network-only（取消 Q 门槛）、完整方法；消融 Q 余量、swap、group、多起点。默认 K8s 调度器需实际部署测量，不能用自行实现的均衡算法冒充。
- η∈{0.7,0.75,0.8,0.85,0.9,0.95}；保持同一需求和 F，报告通信代价、预测余量、实际 Q 和违约。不同 η 的启发式代价可能受局部最优影响，不人为修成单调。
- 最终输出确定性映射、每节点镜像预置清单、保留原始 Pod 规格且设置 nodeName/合法 affinity 的 manifest；检查实际落点、BIRD 邻居与 FIB，再测性能。
- 不把虚拟网络权重称为 Mbps；仅有实测流量时才报告带宽节省。

## 预设验收门槛

- 所有发布的放置满足资源/部署约束，且无超出标定域预测。
- 独立测试 Q 的 MAE≤0.08，95 分位绝对误差≤0.15；同时报告 Q 接近 0.8 的子集误差。
- 对预测安全的独立部署报告实测 Q<0.8 的比例及单侧 95% 二项置信上界，目标上界≤0.10；测试数量不足不能宣称达到该目标。观察独立性按部署区块而非节点采样点计。
- 通信优化效果用重复拓扑/负载下配对比较和置信区间；不预先承诺一定优于所有对照。若无显著改善，解释适用场景而非删掉反例。
- 不满足上述门槛时继续改进模型或收缩**结论适用范围**并给出证据，不将失败试验改写成成功；PDF 的交付项仍需完成。

## 2026-09-20 首轮压力试验冻结

初始 pilot 使用 `calibration.yaml`：3 种规格，每种 4×3 压力网格、2 区块，每点预热 2 秒、测量 8 秒。每个区块首尾无压力基线。固定 canary 单任务为 8 次 1MiB SHA256，持续执行；latency 统计量固定为单任务 p95，同时记录完整任务时延数组。Q 由吞吐与 p95 的区块基线比值取最小。此轮仅诊断，不作为独立最终测试。

压力 CPU 输入是后台 duty-cycle 的目标核数除以 guest CPU 数；内存为驻留字节数除以 guest MemTotal，均保留实际使用指标。固定 canary 代表被测服务，本身消耗 CPU；其存在与资源开销在所有标定/验证中必须一致，不能将该 F 不经验证用于无 canary 的部署。resident 注入维持 RSS，stream 模式在相同 CPU 预算内连续读取内存，供后续预算一致性检查。内存点需保留 MemTotal 的 20% 可用余量，否则保留 rejected 记录而非强行制造 OOM。pilot 尚未安装 K3s，迁移到 K3s 后的基础占用/曲线必须另验证。

## 2026-09-20 正式划分与标定对象冻结

`configs/splits.json` 与每个 profile 的 train/calibrate/test YAML 固定三套压力设计。训练网格 CPU={0,.35,.45,.55,.65,.8,.95} × 内存={0,.3,.6}；独立校准 CPU={.1,.4,.5,.6,.9} × 内存={.15,.45}；最终测试 CPU={.2,.425,.525,.575,.75,.85} × 内存={.1,.4,.6}，包含 resident 与未见 stream 两种实现。各自 5 个随机区块，每点 2 秒预热、10 秒测量、首尾基线。与 pilot 点不同的设计用于加密拐点及可运行内存范围。runner 暂沿用 `pilot` 配置键，实验属性由 `evidenceSplit` 和批次名确定，不由键名决定。

`continueCalibration.py` 只等待既有训练的真实 SSH 进程，随后执行独立校准 → 拟合并冻结模型文件 → 最终测试 → 冻结模型评估。缺少真实进程且未记录完成时停止报错，不重新启动训练。数据处理及源码哈希见各 batch manifest。

路由 pilot 为 12 组满秩特征、每组 3 次，256 个对端静态前缀，稳态 15 秒；原始样本只测目标 BIRD 进程，不包含容器和内核消耗。此轮不作为最终 Pod 总需求系数，目的为检查特征响应和测量可行性。先用单个混合协议样本完成协议门槛验证，后续全部样本记录协议/OSPF/RIB 状态。未配置 kernel protocol，因此不存在本轮 BIRD RIB-to-FIB 写入阶段。

## 2026-09-20 20:48 前置修订：额外实现与画像身份
